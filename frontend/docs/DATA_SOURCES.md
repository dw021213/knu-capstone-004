# 데이터 출처

이 앱이 화면에 보여 주는 데이터의 출처, 버전, 가공 방법을 적습니다. 데이터를 바꾸면 이 문서도 같은 커밋에서 고칩니다.

| 제공       | 안동균(교통 모델) 전달본                                                                     |
| dataset_id | `jeju_h3_r8_road_islands_its20260914_ngii2025_v1`                                            |

### 점수의 뜻

- 날짜와 무관한 공간 점수입니다. 날짜·날씨·교통량·사고 이력을 입력하지 않았으므로 날짜를 바꿔도 값이 같습니다.
- 사고확률이 아닙니다. 백분위는 도로 자료가 있는 셀 2,249개 안에서 매긴 상대 순위(0~100)이고, 높을수록 상대적으로 위험합니다. 백분위 95는 사고확률 95%라는 뜻이 아닙니다.
- 2026년 실제 사고 자료로 정확도를 검증하지 않았습니다. `metadata.json`의 2021년 지표는 과거 평가 값이라 지금의 정확도로 쓰지 않습니다.
- 본섬과 섬의 도로 자료는 둘 다 "2026년 도로 자료"라고 표시하지 않습니다.

### 화면 표시

- 백분위를 5단계로 나눕니다: 90 이상 매우 높음, 70 이상 높음, 30 이상 보통, 10 이상 낮음, 그 아래 매우 낮음.
- 백분위가 빈 1,402개 셀은 데이터 부족으로 회색 빗금을 칩니다. 도로 자료를 확인하지 못했다는 뜻이며 안전하다는 뜻이 아닙니다.

### 파일과 가공

| 파일                          | 설명                                                                                                                                                                     |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `data-src/risk_scores.csv`    | 전달받은 `risk_scores.csv`를 고치지 않고 그대로 둔 원본                                                                                                                  |
| `data-src/risk_metadata.json` | 같은 전달본의 `metadata.json` 정제본. 제공자 PC의 절대경로 값(`model_source`, `model_files[].path`, `input_sources.*.path`)만 파일 이름으로 줄이고 다른 값은 원본 그대로 |
| `public/data/scores.json`     | `npm run data:scores`(`scripts/build-scores.mjs`)로 만든 배포용 파일. 셀마다 `[백분위, 도로 출처 코드]`만 남김                                                           |

`scores.json` 가공 규칙:

- 백분위는 소수 둘째 자리에서 반올림합니다. 빈칸은 `null`입니다.
- 도로 출처 코드는 `ITS_standard_nodelink` → 1(표준노드링크), `NGII_digital_map` → 2(수치지도), `no_mapped_road` → 0(미확인)입니다.
- 원본의 `risk_score`(보정하지 않은 모델 점수)는 싣지 않습니다. 도로 자료가 없는 셀에도 값이 있어 안전 판단에 쓰면 안 되기 때문입니다.

### 백엔드 모드(`VITE_DATA_MODE=api`)

백엔드 `/api/grid?weather=on`의 `hazard_percentile`(유동인구를 끈 교통 모델 백분위)로 색을 칠합니다. `risk_percentile`(유동인구 반영)과 `risk_score`는 읽지 않습니다. 격자 응답에는 표준노드링크·수치지도 구분이 없어서 같은 버전의 `scores.json`에서 도로 출처를 붙입니다.

두 모드의 백분위는 뜻이 다릅니다.

| 모드       | 값                                                       | 날씨                                                                                                                                                                                                                                                                   |
| ---------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `snapshot` | `scores.json`의 교통 모델 백분위                         | 반영하지 않습니다. 날짜와 무관한 공간 점수입니다                                                                                                                                                                                                                       |
| `api`      | 백엔드 `hazard_percentile`(`weather=on`, `at` 시각 기준) | 기상 가산이 들어간 값입니다. 백엔드가 셀마다 가장 가까운 제주 AWS 지점의 관측이 기준을 넘으면 최대 0.3을 더하고 가산 전 분포에 대어 순위를 다시 매깁니다. 가산 전 값은 `base_percentile`이고, 응답의 `weather.status`가 `no_data`면 그 시각 관측이 없어 가산이 0입니다 |

근거: `backend/docs/FRONTEND_API.md`의 기상 가산 절과 `/api/grid` 필드 표(`hazard_percentile`은 "기상 가산 포함", `base_percentile`은 "기상 가산 전"). 기상은 관측 기반이라 미래 시각의 `at`에는 관측이 없을 수 있습니다.

## 배경 지도

OpenStreetMap 표준 타일(`https://tile.openstreetmap.org/{z}/{x}/{y}.png`, ODbL 데이터, 타일 이용은 [OSM 타일 사용 정책](https://operations.osmfoundation.org/policies/tiles/))을 씁니다. 화면에 "© OpenStreetMap contributors"를 [저작권 페이지](https://www.openstreetmap.org/copyright) 링크로 표기합니다. 대량 트래픽에는 쓰지 않고, 배포가 커지면 키가 있는 공급자로 바꿉니다(`src/features/map/basemap.ts`).

받기와 정제는 나뉘어 있습니다. `npm run data:poi:fetch`(`scripts/fetch-poi.mjs`)가 네트워크에서 원본을 받고 지오코딩해 위 원본 파일과 `poi-sources.json`을 고칩니다. `npm run data:poi`는 커밋된 원본만 읽으므로 네트워크 없이 같은 결과가 나옵니다(테스트가 바이트 단위로 확인).

정제 규칙:

- 정제본 형식은 `{ type, status, source, fetchedAt, items: [{ id, type, name, lat, lng, detail }] }`입니다. `status`가 `pending`이면 앱이 '준비 중'으로 보여 줍니다.
- 좌표는 소수 여섯째 자리로 반올림하고 `JEJU_BOUNDS`(32.9~34.05N, 125.9~127.2E) 밖이거나 빈 행은 뺍니다.
- CCTV: 좌표가 소수 다섯째 자리(약 1m)까지 같으면 한 지점으로 합칩니다. 대수는 더하고 목적은 서로 다른 값만 '·'로 잇습니다. 대수가 비면 1대로 셉니다. 이름은 도로명 주소, 없으면 지번 주소(시도명 뺌). `detail`은 `purpose`, `cameras`. id는 이름·좌표 순으로 정렬해 매깁니다.
- 편의점·숙박: 같은 상가업소번호는 한 번만, 상호와 좌표가 모두 같으면 하나만 남깁니다(같은 건물의 다른 업소는 남김). 이름은 상호명(+지점명), id는 `종류-상가업소번호`.
- 경찰: 시도청 '제주청' 행만 씁니다. 이름은 `제주동부경찰서 중앙지구대`처럼 경찰서와 관서. `detail`은 `kind`(지구대/파출소), `address`.
- 지오코딩(경찰·응급실, 32건): Nominatim에 1초에 1건, User-Agent에 저장소 주소를 넣어 질의합니다. 주소 결과가 경찰서·병원이면 그대로 쓰고, 아니면 기관 이름으로 다시 찾고, 그래도 없으면 주소 결과 중 도로명과 건물번호가 맞는 것만 근사 좌표로 씁니다. 결과: 주소로 27건, 이름으로 2건(추자, 대신), 근사 2건(오라, 연동, 결과 주소가 해당 지구대 건물), 실패 1건(외도).
- 전화번호와 개인 이름은 정제본에 넣지 않습니다. 이름은 상호·기관명만 씁니다.
- 응급실은 레이어가 아니므로 `PoiType`에 넣지 않았습니다. 같은 파일 형식이고 항목 `type`은 `er`입니다.
